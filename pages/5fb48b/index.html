静态中断interrupt_before&after

# 总结

  1. 中断

    1. 二者：静态中断，在节点和节点之间，动态中断(interrupt)在节点内的任意位置
    2. 静态中断
      1. 在graph.compile时，使用interrupt_before和interrupt_after，后接List，指定需要静态中断的节点
      2. 使用graph.stream(None, config)，让图继续基于当前中断节点进行运行
    3. 动态中断
      1. 在节点内部任意的地方，使用interrupt进行中断

  2. 适用场景

    1. 大部分 AI Agent 项目（审批流、Copilot、客服Agent、多Agent协作） 都会优先采用 动态中断 interrupt() + Command(resume=...) + Checkpointer 的方案
    2. interrupt_before/after 更多用于调试、流程断点控制或特定审批节点的快速实现
  3. 类型 interrupt_before / interrupt_after interrupt()
    中断时机 编译 Graph 时预先定义 运行时动态决定
    中断位置 Node 执行前或执行后 Node 内部任意位置
    是否需要 update_state 通常需要 不需要
    Human-in-the-loop 适合 更适合
    恢复方式 update_state + 传入 graph.invoke/stream(None, config) 继续执行 通过 Command(resume=value) 传入数据
    灵活性 低 高
    企业项目使用频率 中 高

# 说明

interrupt_before 和 interrupt_after 是 LangGraph 中用来设置“静态断点”的参数，用于在指定节点的执行前或执行后自动暂停整个工作流

参数 中断时机 主要用途
interrupt_before 在指定节点开始执行之前 主要用于前置校验。例如，在执行“发送邮件”或“扣费”等敏感操作前，暂停以便进行人工确认或检查权限。
interrupt_after 在指定节点执行完成之后 主要用于结果审核。例如，在AI生成内容或调用API后，暂停以便人工检查结果，再决定是否继续下一步。

这两个参数是在调用 graph.compile() 编译图时配置的，并且必须配合一个检查点 (checkpointer) 使用，用来保存中断时的状态

from langgraph.checkpoint.memory import MemorySaver

# 创建一个检查点，用于保存状态
memory = MemorySaver()

# 假设你已经构建好了图
# graph = StateGraph(State)...

# 编译图时，配置中断点：
# 1. 在 node_b 执行前中断
# 2. 在 node_c 执行后中断
app = graph.compile(
    checkpointer=memory,  # 必须配置
    interrupt_before=["node_b"], 
    interrupt_after=["node_c"]
)

# 动态中断VS静态中断

interrupt_before和interrupt_after这两个是静态中断，主要用作“调试断点”，方便检查状态，但无法在恢复时接收新的外部输入。

如果需要真正的人机交互（如审批、获取用户额外信息），通常更推荐使用动态中断（interrupt() 函数）。它能让工作流在节点内部暂停并等待用户输入，实现“你问我答”的效果。
