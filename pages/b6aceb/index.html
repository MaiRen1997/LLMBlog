Command和update_state不同

# 中断恢复后两种不同的交互模式

# 区别

  1. Command
    1. 会将用户的输入，传递给interrupt定义的地方，然后依据interrupt的值写的逻辑，进行运行
    2. 每次用户输入，图的运行都会从开始节点，重新运行，之前的状态，会从Checkpoint获取
  2. update_state
    1. 直接修改检查点中的状态，然后用 stream(None) 继续
    2. 图从修改后的位置继续
维度 Command(resume=...) graph.update_state()
使用场景 标准的中断恢复，传递用户输入给中断点 手动编辑/修正图的状态，绕过正常流程
恢复方式 执行图，从节点开头恢复，interrupt() 返回传入值 直接修改检查点中的状态，然后用 stream(None) 继续
适用情况 用户回答了问题、做出了审批决策 你想“修正”AI的工具调用、删除错误消息、手动注入内容
是否需要重新执行节点中的代码 是
节点从头开始执行，中断点前的代码会重新运行		 否——
状态被直接修改，图从修改后的位置继续

# 代码片段示例

# Command

from langgraph.types import Command

# 图被中断后，用户输入了答案
graphInstance.invoke(Command(resume="25岁"), config=thread_config)

# update_state

from langgraph.checkpoint.memory import MemorySaver

graph = builder.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["tools"]  # 在执行 tools 节点前中断
)

# 执行图，会在 tools 节点前暂停
for event in graph.stream(initial_input, config):
    print(event)

# 获取当前状态
state = graph.get_state(config)

# 手动修改状态（例如：修正AI的工具调用参数）
existing_message = state.values["messages"][-1]
existing_message.tool_calls[0]["args"]["query"] = "修正后的搜索词"

# 更新状态，并指定这个修改是哪个节点做的
graph.update_state(config, {"messages": [existing_message]}, as_node="chatbot")

# 继续执行
for event in graph.stream(None, config):
    print(event)

# Command

工作流程：

  1. 图中断在 interrupt() 这一行
  2. 外部调用 Command(resume="25岁")
  3. 图从节点开头重新执行
  4. interrupt() 函数返回 "25岁"，代码继续执行

⚠️ 关键特性：节点中 interrupt() 之前的代码会重新执行。如果你的节点里调用了 API，务必把 API 调用放在 interrupt() 之后，否则会重复执行。

典型使用场景：

  • 用户回答一个问题（“你多大了？” → “25岁”）
  • 用户做出审批决策（“批准”或“拒绝”）
  • 用户提供缺失的信息

# '图实例'.update_state()

这种方式不是在恢复 interrupt()，而是在修改图的持久化状态。

通常与 interrupt_before/interrupt_after 配合使用，在图的节点之间中断（而非节点内部）：

from langgraph.checkpoint.memory import MemorySaver

graph = builder.compile(
    checkpointer=MemorySaver(),
    interrupt_before=["tools"]  # 在执行 tools 节点前中断
)

# 执行图，会在 tools 节点前暂停
for event in graph.stream(initial_input, config):
    print(event)

# 获取当前状态
state = graph.get_state(config)

# 手动修改状态（例如：修正AI的工具调用参数）
existing_message = state.values["messages"][-1]
existing_message.tool_calls[0]["args"]["query"] = "修正后的搜索词"

# 更新状态，并指定这个修改是哪个节点做的
graph.update_state(config, {"messages": [existing_message]}, as_node="chatbot")

# 继续执行
for event in graph.stream(None, config):
    print(event)

# 如何选择

你的需求 推荐方式
用户回答问题、提供输入、审批决策 Command(resume=...)
想修正 AI 已经生成的内容（工具调用参数、消息内容） graph.update_state()
想在恢复时同时做两件事：传用户输入 + 修改状态 Command(resume=..., update={...})
想手动控制图的下一个节点（路由） Command(goto="node_name")

你可以同时使用它们：Command(resume="批准", update={"approved": True}) 可以在恢复用户输入的同时更新状态。
