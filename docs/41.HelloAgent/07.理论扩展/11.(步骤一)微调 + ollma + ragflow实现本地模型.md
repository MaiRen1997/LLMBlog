## 第一步：从 LLaMA Factory 导出模型

1. 在 LLaMA Factory 的 WebUI 中，切换到 **Export** 选项卡，配置以下参数：

   | 参数                 | 设置建议                   | 说明                                       |
   | :------------------- | :------------------------- | :----------------------------------------- |
   | **模型名称**         | 保持默认（你的基座模型名） | 自动填充你微调时使用的模型                 |
   | **检查点路径**       | 选择最优的检查点文件夹     | 如 `./output/your_project/checkpoint-1200` |
   | **输出目录**         | 新建一个干净文件夹         | 用于存放导出后的模型文件                   |
   | **模型最大分片大小** | 建议 2-5 GB                | 避免单文件过大导致加载问题                 |

   点击 **开始导出**，等待转换完成。导出成功后，输出目录中应包含：

   - `.safetensors` 文件（模型权重）
   - `config.json`、`tokenizer.json` 等配置文件
   - **Modelfile**（Ollama 所需的配置文件）

   > ⚠️ **注意**：新版 LLaMA Factory 导出时会**自动生成 Modelfile**。如果没生成，你可以手动创建（见下文）。

## 🚀 第二步：导入 Ollama

### 2.1 确认导出目录结构

确保你的导出目录包含类似以下文件：

```text
/path/to/exported_model/
├── config.json
├── generation_config.json
├── model-00001-of-00002.safetensors
├── model-00002-of-00002.safetensors
├── tokenizer.json
├── tokenizer_config.json
└── Modelfile          # 关键！Ollama的配置文件
```

### 2.2 导入模型到 Ollama

打开终端，切换到导出目录，执行以下命令：

```bash
cd /path/to/exported_model
ollama create your-model-name -f Modelfile
```

> `your-model-name` 可自定义，如 `my-finetuned-qwen`。

### 2.3 验证导入是否成功

```bash
ollama list
```

应该能看到你刚创建的模型出现在列表中。

### 2.4 测试模型是否正常工作

```bash
ollama run your-model-name "你好，请介绍一下你自己"
```

如果模型正常回复，说明导入成功。

## 🔧 第三步：配置 RAGFlow 调用 Ollama 模型

### 3.1 前提：RAGFlow 已部署

如果你还没部署 RAGFlow，可以用 Docker 快速启动：

```bash
docker pull ragflow/ragflow:latest
docker run -d --name ragflow \
  -p 7860:7860 \
  -v /path/to/data:/data \
  ragflow/ragflow
```

访问 `http://localhost:7860` 进入 RAGFlow 界面。

### 3.2 配置 Ollama 作为模型供应商

RAGFlow 支持通过 **OpenAI-API-Compatible** 方式接入 Ollama：

1. 登录 RAGFlow，点击右上角头像 → **模型供应商**
2. 找到 **OpenAI-API-Compatible**，点击「添加模型」
3. 填写配置：

| 配置项            | 填写内容                               | 说明                              |
| :---------------- | :------------------------------------- | :-------------------------------- |
| **模型类型**      | `chat`                                 | 大语言模型选择对话类型            |
| **模型名称**      | `your-model-name`                      | 与 ollama create 时的名称一致     |
| **基础 URL**      | `http://host.docker.internal:11434/v1` | Ollama API 地址                   |
| **API-Key**       | 任意值（如 `ollama`）                  | Ollama 不需要真实密钥，但必须填写 |
| **最大 token 数** | `4096` 或根据模型填写                  | 可根据模型上下文长度调整          |

> **注意**：如果 RAGFlow 也在 Docker 中运行，基础 URL 应使用 `http://host.docker.internal:11434/v1` 而非 `localhost`，因为 Docker 容器内的 localhost 指向容器自身。

### 3.3 配置 Embedding 模型（可选但推荐）

如果想让知识库检索效果更好，还需添加一个 Embedding 模型：

- 重复上述步骤，在 OpenAI-API-Compatible 中「添加模型」
- 模型类型选择 `embedding`
- 模型名称填写 Ollama 支持的嵌入模型，如 `nomic-embed-text` 或 `bge-m3`

首先确保 Ollama 已拉取该嵌入模型：

```bash
ollama pull nomic-embed-text
```



## 🧪 第四步：验证与使用

### 4.1 设置默认模型

在模型供应商页面，点击「设置默认模型」，将聊天模型设为你刚添加的微调模型。

### 4.2 创建知识库

1. 进入「知识库」页面，点击「创建知识库」
2. 嵌入模型选择你配置的 embedding 模型
3. 上传文档，等待解析完成

### 4.3 创建聊天助手并测试

1. 进入「聊天」页面，点击「新建助理」
2. 选择你创建的知识库
3. 在模型设置中选择你的微调模型
4. 开始提问，测试 RAG 效果

## 📝 常见问题排查

| 问题                    | 可能原因                       | 解决方案                                                     |
| :---------------------- | :----------------------------- | :----------------------------------------------------------- |
| `ollama create` 失败    | Modelfile 中的 FROM 路径不正确 | 检查 FROM 指向的是否是正确的模型文件路径                     |
| RAGFlow 无法连接 Ollama | 网络不通或 URL 错误            | 确认 URL 使用 `host.docker.internal`，检查 Ollama 服务是否运行 |
| 模型回复乱码或无意义    | 模板 TEMPLATE 不匹配           | 确保 Modelfile 中的 TEMPLATE 与模型格式一致                  |
| 检索结果不相关          | 嵌入模型选择不当               | 使用中文优化的嵌入模型，如 `bge-large-zh`                    |

## 💎 总结

整个流程可以归纳为三个核心步骤：

1. **LLaMA Factory 导出**：选择最优检查点，导出为 safetensors 格式 + 自动生成 Modelfile
2. **Ollama 导入**：`ollama create` 命令创建本地模型
3. **RAGFlow 配置**：通过 OpenAI-API-Compatible 方式接入 Ollama 服务

完成以上配置后，你就拥有了一个**“微调定制 + 知识库增强”**的完整 RAG 系统。微调让模型更懂你的业务风格，RAG 给它提供实时、准确的外部知识，两者结合能大幅提升问答质量。
