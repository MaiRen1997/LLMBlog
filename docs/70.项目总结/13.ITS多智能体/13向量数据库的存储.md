### 定义常用方法

#### 将切分的文档保存到向量数据库

1. 注意此处使用的range，设置的步长是2
2. 使用`向量数据库实例.add_documents`添加文档

```python
    def  add_documents(self,documents:list,batch_size:int=16)->int:
        """
        将切分之后的文档块保存到向量数据库中

        Args:
            documents: 切分之后的文档块
            batch_size: 分批保存文档块的批次大小

        Returns:
            int:成功添加到向量数据库中文档块的数量(服务前端展示)

        """

        # 1. 获取到文档块的总数量
        total_documents_chunks=len(documents)

        # 2. 分批次保存
        # 场景：documents:[1,2,3,4,5] batch_size:2 遍历3次 第一次取到[1,2]  第二次取到[3,4]    第三次取到[5]
        documents_chunks_added=0
        try:
            for i in range(0,total_documents_chunks,batch_size):
                bath=documents[i:batch_size+i]
                self.vector_database.add_documents(bath)
                documents_chunks_added=documents_chunks_added+len(bath)
                logger.info(f"成功将文档块:{documents_chunks_added}/{total_documents_chunks}保存到向量数据库...")
                return documents_chunks_added
        except Exception as e:
            logger.error(f"文档块列表:{documents}保存到向量数据库失败: {str(e)}")
            raise e
```

### 文档分割

1. 为什么文档切割
   1. 防止token限制
   2. 内容过多，产生噪音，造成LLM参考的上下文不精准，回复质量不高
      1. 可以使用模型对检索的大量内容chunk做降噪
         1. 让LLM只做提取，不修改
         2. 让LLM进行总结
         3. 让嵌入模型对检索内容，做二次向量化，优化chunk
2. 检索尽量使用多路召回
   1. 用户提出一个问题，通过大模型，生成多个相似的问题：(比如生成了四个)
   2. 根据问题，检索每个问题对应的答案：(比如：一个问题对应4个答案，4个问题，就对应16个答案)
   3. 召回后进行去重：(对16个答案进行去重，比如保留了10个答案)
   4. 内容过多，可以使用压缩(降噪)
      1. 让模型按照提取、总结、二次向量化等方法，保留精简的答案：(比如4个)，然后输出
3. 动态机制切分
   1. 如果文档内容不大，直接将这内容作为一个chunk(不用切分)
   2. 如果内容比较大，分析大内容的数据结构，然后为他定制切分策略。
      1. 采用header rejection:标题注入（保留每一块的业务背景、上下文）：比如切分了解决方案1，要额外加上设备类型、型号、报错的背景等
4. 使用`RecursiveCharacterTextSplitter`进行文档分割
   1. 大小`chunk_size`
   2. 重合度`chunk_overlap`
   3. 分割符`separators`
5. [常用6个分割方法参考](https://mairen1997.github.io/LLMBlog/pages/b0be9b/#%E6%96%87%E6%A1%A3%E5%88%86%E5%89%B2)
   1. 使用`切分器实例.split_documents`进行文档切分
   2. 使用`filter_complex_metadata`过滤，不被向量数据库支持的元数据

```python
    for doc  in documents:

    # 2.切分文档得到文档块列表

    # b.如果内容比较大，分析大内容的数据结构，然后为他定制切分策略。采用header rejection:标题注入（保留没一块的业务背景、上下文）

                final_document_chunks.extend(documents_chunks_list)

                clean_documents_chunks=filter_complex_metadata(final_document_chunks)

                #  4. 无效性检查（校验page_content的是否合法（不能为空））
                valid_documents_chunks=[document for document in  clean_documents_chunks if document.page_content.strip()]

                if not valid_documents_chunks:
                    logger.error("切分后的文档块没有任何的内容")
                    return 0

                # 5 .存储文档块到向量数据库
                total_documents_chunks=self.vector_store.add_documents(valid_documents_chunks)


                # 6 .返回保存成功的文档块数
                return total_documents_chunks
```

```python
    """
    文档摄入类：（摄入：加载、切分、存储）
    """

    def __init__(self):

        self.vector_store = VectorStoreRepository()
        self.document_spliter=RecursiveCharacterTextSplitter(
            chunk_size=1500,  # 长文档内容分块的阈值（略大一些。永远考虑语义优先）

                "\n## ",
```
